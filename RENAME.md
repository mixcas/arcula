# Renaming Custodia to Arcula

The project was called **Custodia**; it is now **Arcula** (`arcula.art`,
purchased 28 September 2026). This file records what changed, what deliberately
did not, and how to finish the job.

The short version: **the public name changed, the internal identifiers did
not.** Everything a visitor can see says Arcula. Everything a machine reads —
the Firebase project id, the emulator project id, the package and repository
names — still says `custodia`, because renaming those is a migration with real
downtime, not a find-and-replace.

## Favicon

`public/favicon.svg` is the source of truth — a single-path glyph in
`#2B2927`, hand-supplied. Every raster size beside it is generated from that
file rather than drawn separately: `favicon.ico` (16/32/48px, PNG-compressed),
`favicon-32.png`, `apple-touch-icon.png` (180×180), `icon-192.png`,
`icon-512.png`, and `icon-maskable-512.png`.

`icon-maskable-512.png` is the one to regenerate if the glyph ever changes: the
transparent 512 is declared `"purpose": "any"`, and Android crops a maskable
icon to a circle or squircle, which clips this glyph where its spikes reach the
edge of the viewBox. The maskable variant is the same path at 80% scale on an
opaque `#2B2927` ground, in `#F5F2ED`.

## The one real trap: `demo-custodia`

One string, two files:

- `package.json:16` — the `test:rules` script passes `--project demo-custodia`
- `tests/firestore.rules.test.ts:42` — `const PROJECT_ID = "demo-custodia"`

Change one without the other and `bun run test:rules` points the suite at a
different project than the test asserts against. Everything else in this
document is cosmetic; this is the only item where a partial rename breaks the
build.

## Migrating the Firebase project

Renaming `custodia-67307` is not an edit — it is a new project. Roughly in
order:

1. Create the new Firebase project.
2. **Authentication → Settings → Authorized domains**: add the new project's
   `web.app` host. This is the step that silently breaks sign-in if skipped.
3. Copy the Firestore data. The collections hold real user data, so this wants
   an export/import or a scripted copy — not a fresh start.
4. `bun run deploy:rules` against the new project, so the database is never
   briefly unprotected.
5. Update `.env` / `.env.development` with the new web app config
   (`VITE_FIREBASE_*`). These values are per-project and the app will not
   connect without them.
6. Update `.firebaserc:3` to the new project id.
7. `bun run deploy` and verify sign-in plus one collection read.

Add `arcula.art` to Authorized domains at the same time as step 2 if the custom
domain is live.
